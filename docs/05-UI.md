# UI Specification V1

---

## 1. Arah desain

Enterprise dashboard — clean, minimal, **data dense**, desktop-first, profesional.
Bukan aplikasi marketing: hindari gradient berlebihan, animasi ramai, ilustrasi besar.

| Prinsip | Penerapan |
|---|---|
| Angka dulu | KPI dan tabel diprioritaskan di atas dekorasi |
| Drill-down | Setiap angka penting bisa diklik sampai daftar customer |
| Jujur soal data | Angka tidak akurat diberi badge (`PARTIAL`, `NEEDS REVIEW`, `belum dikurangi retur`) |
| Konsisten | Semua tabel memakai komponen DataTable yang sama |
| Desktop-first | Banyak tabel & heatmap lebar; mobile cukup dapat dibaca, bukan prioritas |

### 3.1 Otorisasi tidak boleh bergantung route saja

Middleware menyaring per-**path**, sedangkan **action id Next.js bersifat global** —
Server Action apa pun bisa dipanggil lewat POST ke path mana pun yang boleh diakses
pemanggil. Karena itu:

> **Setiap Server Action dan route handler WAJIB punya `requireRole` sendiri,
> termasuk action BACA.** Middleware adalah lapis pertama, bukan satu-satunya.

| Kelompok action | Guard | Alasan |
|---|---|---|
| `customers-actions.ts` (semua) | `requireRole("ADMIN","CRM")` | Mengembalikan nama, No. HP, alamat, riwayat transaksi |
| `workspace-actions.ts` (semua) | `requireRole("ADMIN","CRM")` | Baris task memuat identitas customer |
| `analytics-actions.ts` | `requireRole("ADMIN","CRM","MANAGEMENT")` | Agregat, tanpa PII per-customer |
| `product-mapping-actions.ts`, `import-admin-actions.ts`, `users-actions.ts` | `requireRole("ADMIN")` | Administrasi data & akun |
| `cluster-rules-actions.ts`, `reconciliation-actions.ts` | `requireRole("ADMIN","MANAGEMENT")` | Referensi & angka agregat |
| `/api/import/*` | `requireRole("ADMIN")` + Zod | Menulis canonical |
| `/api/customers/*`, `/api/workspace/*` | `requireRole("ADMIN","CRM")` + Zod | Export berisi PII |

Seluruh parameter dari client divalidasi Zod (`src/lib/list-filter-contracts.ts`)
— `z.object()` juga MEMBUANG key asing sehingga tidak ada properti tak dikenal
yang sampai ke pembangun SQL.

Sesi memakai JWT (12 jam), jadi `requireSession` **memeriksa status aktif user ke
DB**: akun yang dinonaktifkan di halaman Users langsung kehilangan akses tanpa
menunggu token kedaluwarsa. Pemeriksaan itu dimemo per-request.

Regression test: `tests/server-action-security.test.ts` (137 test) memanggil setiap
action secara langsung sebagai MANAGEMENT, sebagai role yang berhak, dan tanpa sesi.

### 3.2 Import Exclusion vs Needs Review — dua hal berbeda

| | Import Exclusion | Needs Review |
|---|---|---|
| **Satuan** | baris file | customer |
| **Arti** | Baris TIDAK PERNAH jadi canonical customer/order | Customer SUDAH valid, tapi keputusan cluster-nya bergantung data belum pasti |
| **Kode** | `MISSING_PHONE`, `INVALID_PHONE`, `MISSING_NAME`, `INVALID_DATE` | `UNKNOWN_PRODUCT` (F≤2), `GROUP_STATUS_CONFLICT` |
| **Masuk RFM/Cohort/Cluster?** | Tidak pernah | Ya, tapi cluster = `NEEDS_REVIEW` |
| **Cara menyelesaikan** | Perbaiki di file sumber, upload ulang | Product Mapping / keputusan membership |
| **Halaman** | Data Quality | Customer Cluster, Product Mapping |

`NEEDS_REVIEW` **tidak pernah** dibuang ke Cluster F, dan tidak pernah dicampur
dengan exclusion. Keduanya tampil terpisah di halaman Reconciliation lengkap
dengan label satuannya.

## 4. Komponen shadcn

```
Sidebar · Card · Button · Badge · Tabs · Table · Sheet · Dialog · AlertDialog
Select · Input · Command · Popover · Calendar · Tooltip · Progress · Skeleton
ScrollArea · DropdownMenu · Separator · Sonner
```

- **DataTable** = TanStack Table + styling shadcn. Satu komponen dipakai semua halaman.
  Fitur: sort, filter, pagination server-side, column visibility, export CSV.
- **Heatmap** = komponen custom (CSS Grid). Recharts tidak punya heatmap.

### Skala warna heatmap
Sekuensial satu warna, gelap = tinggi. Sel `PARTIAL` diberi garis diagonal + badge.
Nilai kosong (cohort belum mencapai bulan itu) dibiarkan kosong, bukan 0%.
Kontras teks wajib memenuhi WCAG AA di sel tergelap dan terterang.

## 9. Loading & error

- Skeleton untuk KPI, chart, dan tabel — bukan spinner layar penuh
- Import memakai Progress bertahap dengan langkah tertulis
- Error import ditampilkan lengkap dengan nomor baris sumber
- Toast (Sonner) untuk aksi singkat; AlertDialog untuk aksi berisiko (commit, recalculate)
